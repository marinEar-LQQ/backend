# marinEar 인식 오류 줄이기 — 실험 기록

> 목적: 무전 교신에서 **선박명·장소·숫자 같은 핵심 정보를 틀리지 않게** 하는 것.
> 원칙: 맞히는 것만큼 **틀린 걸 확정하지 않는 것**이 중요하다. 불확실하면 "확인 필요"로 남긴다.
> 모든 수치는 합성 음성(TTS)에 잡음을 섞은 녹음 기준이다. 실제 무전 환경의 성능이 아니다.

## 측정 방법

- **평가 세트:** 녹음 파일 + 정답 대본(`fixtures/audio/*/truth.json`). 대본마다 핵심어 목록(선박명, 장소, 속력, 거리, 시각 등)을 함께 둔다.
- **지표**
  - **CER (글자 오류율):** 정답 대비 틀린 글자 비율. 낮을수록 좋다.
  - **핵심어 적중:** 핵심 정보가 받아쓰기에 들어 있는지. "12노트"와 "열두 노트"처럼 같은 뜻의 표기는 모두 정답으로 인정.
  - **터미널·선석:** 엔진 추출기가 정답과 같은 값을 뽑았는지.
- **도구:** `scripts/eval-asr.ts` — 같은 녹음을 여러 방식(원음 / 잡음 제거 / 모델)으로 처리해 같은 조건에서 비교한다.

```
npx vite-node --config vitest.config.ts scripts/eval-asr.ts <wav...>
  VARIANTS=raw,dsp,dfn12,cleanvoice   비교할 잡음 제거 방식
  GEMINI_MODEL=gemini-3.5-flash-lite  온라인 받아쓰기 (없으면 오프라인 whisper-small)
  VOCAB="한라호,동방호"                받아쓰기 힌트 (작업 등록 선박명)
```

## 처리 흐름 (오류를 줄이는 장치가 들어간 곳)

```
녹음 → ① 말 구간 자르기 → ② 원음 + 잡음 제거음 두 개 만들기
     → ③ 받아쓰기 (힌트: 등록 선박명, 터미널 코드)
     → ④ 두 받아쓰기 비교 (엇갈린 단어 = 확인 필요)
     → ⑤ 정보 추출 (오인식 후보 사전: "펜트"→HPNT? 는 확정 안 함)
     → ⑥ 작업 기록과 비교 → 일치 / 차이 / 확인 필요 / 무관 / 미확정
     → ⑦ 번역: 정형 요약 카드(값은 그대로) + 문장 번역
```

| 단계 | 오류를 줄이는 장치 | 근거 |
|---|---|---|
| ② | 원음과 잡음 제거음을 **둘 다** 인식 | 실측상 잡음 제거가 녹음마다 득이 되기도, 해가 되기도 함 |
| ③ | 등록 선박명·터미널 코드를 힌트로 제공 ("들린 경우에만 쓰라") | 선박명 오인식이 가장 많았음 |
| ③ | 반복 환각 차단, "시청해주셔서 감사합니다" 같은 환각 문장 제거, 지시문 복창 감지 | 실측에서 모두 발생 |
| ④ | 두 결과가 엇갈리면 확정하지 않음 (`ASR_DISAGREEMENT`) | 한쪽만 맞는 경우가 많음 |
| ⑤ | 실측 오인식 표기는 후보로만 연결 (`ASR_CONFUSABLE`) | "HPNT→펜트", "PNIT→TNIC" |
| ⑦ | 핵심 값은 번역 모델에 맡기지 않음 | 번역 모델이 "현대부산호"→"Modern coral"로 지어냄 |

## 실험 기록 (시간순, 2026-11-27)

### 1. 오프라인 whisper-small (브라우저 안)
- 깨끗한 TTS: 터미널 코드 정답 4/6 판정. **강한 잡음 팀 녹음: 핵심어 1/12**, HPNT→"펜트", PNIT→"PNIC".
- 속도: 노트북 Chrome WASM 발화당 약 10초 (RTF 2.4). WebGPU 는 오히려 2배 느렸음 → WASM 채택.
- **조치:** 실측 오인식 표기를 "오인식 후보 사전"으로 등록 (확정하지 않고 후보로만 표시).

### 2. 잡음 제거 비교 (같은 받아쓰기 모델, CER %)
| 녹음 | 원음 | 우리 DSP | RNNoise | Cleanvoice | DeepFilterNet 12dB |
|---|---|---|---|---|---|
| 팀 대본 1 (강한 잡음) | 38~44 | 36~47 | 89 | 46 | 37 |
| mono (일상 대화) | 16~28 | **12~16** | 56 | 52 | 12 |

- **결론:** 세게 지울수록 인식이 나빠진다. 사람 귀에 깨끗한 소리 ≠ 인식에 좋은 소리.
- 우리 DSP(대역 필터 + 살살 깎기)가 가장 안정적 → **기본값 유지**. 나머지는 코드만 보존.

### 3. 모델 크기·특화 모델
- large-v3-turbo: CER 은 낮아졌지만 코드 오인식은 그대로, 1GB·2배 느림 → 미채택.
- 한국어 특화 whisper-small: 순수 한국어는 좋아짐(어선 73%→48%), **영어·코드는 붕괴**(영어 섞인 대본 55%→86%) → 미채택.

### 4. 온라인 전환 (Gemini 받아쓰기 + NVIDIA 번역)
- 약한 잡음 시연 녹음: CER **29%→13%**, 9%, 21%. 터미널·선석 정답. 발화당 처리 10초→**4.4초**.
- NVIDIA 번역: "생각 단계"를 끄자 문장당 17초→**1~3초**, 품질 유지.
- 강한 잡음에서는 힌트로 준 코드(BNCT)를 안 들렸는데 적은 사례 → 교차 검사 유지 필요.

### 5. 새 시연 녹음 (독백 3개, 약한 잡음)
| 녹음 | 온라인 CER | 핵심어 | 놓친 것 |
|---|---|---|---|
| 대본 1 입항 보고 | 6.7% | 4/7 | 한라호→"한라오", **12노트→"10노트"**, 신선대부두 3번 |
| 대본 2 엔진 고장 | 2.8% | 6/7 | 동방호→"공방호" |
| 대본 3 어선 연락 | 10.3% | 8/9 | 제7해진호→"내 칠레진호" |

- **발견:** 남은 오류의 대부분이 **선박명**. 숫자 오인식(12→10)은 원음·잡음 제거음이 **같이 틀려** 교차 검사로도 못 잡음 — 가장 위험한 유형.
- **조치:** 작업 등록 선박명을 받아쓰기 힌트로 자동 전달 → 6장.

### 6. 선박명 힌트 · 모델 선택 · 한도 대비 (독백 3개)
핵심어 합계(23개), 원음 기준:

| 조건 | 핵심어 | CER | 22초 녹음 처리 |
|---|---|---|---|
| flash-lite, 힌트 없음 | 18/23 | 3~10% | ~2초 |
| flash-lite + 선박명 힌트 | 21/23 | 2.9~6.9% | ~2초 |
| **flash + 선박명 힌트** | **23/23** | 0~6.7% | 9~46초 (들쭉날쭉) |

- **선박명 힌트:** 작업에 등록한 자선·상대선 이름을 받아쓰기에 자동으로 넘긴다 (`core.ts` → `ctx.vocabulary` → `/api/transcribe` hints). 한라오→한라호, 칠레진호→제7해진호가 고쳐짐.
- **숫자 오류(12→10노트):** flash 에서만 바르게 들림. lite 는 원음·완화음 모두 "10노트" → 교차 검사로 못 잡는 유형이라 **정확한 모델이 1순위**인 이유.
- **lite 가 남긴 오류:** 동방호→"공방호/홍방호"(힌트를 줘도), "신선대부두 3번에"→"세 번째".
  - "세 번째"는 규칙으로 보완: 터미널 이름 바로 뒤 "N번째"도 선석으로 추출 (`extract.ts`, 테스트 추가).
- **속도와 정확도 절충:** flash 를 먼저 쓰고 20초 안에 답이 없으면 lite 로 넘어간다 (`server/index.ts`, `ASR_TIMEOUT_MS`).
- **무료 한도(429):** 평가를 여러 번 돌리자 flash 의 하루 한도가 소진됨. 시연 당일에도 생길 수 있는 위험.
  - 조치: 중계 서버가 flash(주 키 → 예비 키) → lite(주 키 → 예비 키) 순으로 자동 전환. 잘못된 키는 서버가 떠 있는 동안 다시 쓰지 않음.
  - 남은 대비: 유효한 예비 키 준비, 시연 전날 평가 반복 자제, 시연 영상 백업, 고정 결과 모드("시연 데이터" 표시).

### 7. 추출 규칙 보완 (새 녹음 대본 기준)
- 장소(오륙도·팔미도·부산 남쪽 바다 등), 신선대부두(오인식 "신선대부도" 포함), 채널 "16번 채널", 거리 "2마일/500미터", 지시(비켜·떨어져·기다려·오른쪽/왼쪽으로·엔진 문제·끌어 줄 배)를 추출.
- 선박 불확실 표시는 **이름별로**: 양쪽 인식에 모두 들린 이름은 확정, 한쪽에만 들린 이름만 `[제7해진호 / 칠레진호]`.
- 요약 카드는 양쪽에서 들린 값만 확정, 한쪽만 들린 값은 `[a / b] (확인)`.
